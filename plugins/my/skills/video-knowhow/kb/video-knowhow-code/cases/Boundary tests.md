# Case: six boundary tests

These six scenes are tests of what code could do, run in a session of the earlier production. Their videos are not preserved, and every judgment of quality here is the assistant's report. The page is a record of those tests.

The assistant ran six five-second, 1280×720, 30 fps scenes through one Canvas, Chrome, and ffmpeg harness, then joined them into a 30-second reel. Each scene was drawn as a function of frame time. The chatlog shows the commands for reviewing stills and revising, the completed renders, and an ffmpeg frame count of 150 for each clip. The six videos are named in the chatlog and are not preserved here, so their *visual quality* rests on the assistant's assessment. The scene code and the render counts can be read directly in the chatlog. ## What these tests separate

The chart and the ocean show two different things code does well: **exact symbolic content**, such as labels and computed values, and **coherent procedural fields**, such as a sea whose waves and light agree. The photo and the fox show what an existing image contributes. The detail is already there and code can animate it, but a new view or a new object needs more source information or a fuller scene model. The cat and the person test performance: a motion path or an inverse-kinematics solution can be mathematically correct and still look unconvincing. These readings come from this small set of six tests.
