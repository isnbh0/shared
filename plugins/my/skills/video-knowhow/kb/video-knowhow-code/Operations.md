# Operations

In code-authored video, a named effect or format is usually several smaller operations working together. A “typewriter title” needs text, a type style, a place in the frame, a rule for revealing characters, and enough time to read the result. The [capabilities over features](https://wiki.g15e.com/pages/Capabilities%20over%20features.md) principle suggests learning those reusable [operations](Glossary.md#operation) before collecting effect names. Each operation on this page is small enough to combine independently with the others.

The [theory map](maps/Theory.md) describes the perceptual and design problems these operations can address, the [technique map](maps/Techniques%20and%20approaches.md) shows ways to implement them, and the [recipes](maps/Recipes.md) trace specific combinations with evidence. Each pattern below names a relationship you can control; whether it works depends on visual direction and review.

## A common interface

Visual sources may be text, paths, pixels, footage, or geometry. Audio sources may be recordings or generated signals. Scene code can pass either kind of source through parameters and a shared time coordinate, then combine the results. The interface worth keeping in mind is conceptual:

```text
sources + parameters + time → visible layers and audible signals
visible layers + audible signals → rendered output
rendered output + intended effect → observations and revisions
```

One operation's output should be usable as another's input. A text source can be measured and placed, given a color role, animated over time, and composited over a photograph, and one event on a beat can set both that title's entrance and a sound's onset. That is what lets representation, timing, and sound choices be made separately and then recombined. [Representation models](knowledge/Representation%20models.md) explains what each source retains for later control; [capability boundaries](knowledge/Capability%20boundaries.md) explains what still has to be supplied.

## Describe and organize the sources

| Pattern | Input → operation → output | Design relation and limit |
| --- | --- | --- |
| **Expose a decision as a parameter** | A chosen title, palette, count, camera distance, tempo, or duration → give it one named value and a clear scope → dependent elements can use the same decision. | Supports coherent revision and variants. A parameter is useful when it corresponds to a decision a maker can judge; changing it may still cause layout or timing collisions. [Iteration and parameterization](knowledge/Iteration%20and%20parameterization.md). |
| **Represent a source** | Content and an appropriate form—text, data, path, sprite, image, footage, model, recorded sound, or synthesis rule → make it available to the scene → an editable object, image layer, or audio signal. | The form determines what can be changed later. A single photograph supplies its photographed view; a modeled object can supply new views if its unseen surfaces and materials have been authored. [Representation models](knowledge/Representation%20models.md), [assets and provenance](knowledge/Assets%20and%20provenance.md). |
| **Encode meaning in a visual property** | A value or category, a mapping rule, and a visual channel such as position, length, shape, color, or text → apply the mapping → marks whose visible differences carry information. | This is the core of a chart, status display, or game-state indicator. The mapping has to preserve the intended order or categories; color alone can be insufficient when accurate recognition matters. [Visual hierarchy and composition](knowledge/Visual%20hierarchy%20and%20composition.md), [accessibility and perception](knowledge/Accessibility%20and%20perception.md). |
| **Bind a role to a visual language** | Roles such as primary message, support, background, warning, or character identity plus type, color, spacing, and motion tokens → assign the tokens consistently → related elements share a recognizable treatment. | A role system helps the eye distinguish importance and helps a piece keep its identity across scenes. The roles themselves are choices about meaning. [Attention and hierarchy](theory/Attention%20and%20hierarchy.md), [Visual identity and style](theory/Visual%20identity%20and%20style.md), [visual hierarchy and composition](knowledge/Visual%20hierarchy%20and%20composition.md). |
| **Relate elements in space** | Sources, viewport, anchors, bounds, scale, and alignment rules → place and size elements relative to the frame or one another → a layout that can be evaluated at an output size. | Alignment and proximity can group information; scale and separation can establish a reading order. A new language, aspect ratio, or camera crop may change measured bounds and break the relation. [Grouping and continuity](theory/Grouping%20and%20continuity.md), [visual hierarchy and composition](knowledge/Visual%20hierarchy%20and%20composition.md), [typography in motion](knowledge/Typography%20in%20motion.md). |
| **Combine and reveal layers** | Two or more visual layers plus order, opacity, clipping, masks, or blend rules → composite them → one image that can itself become a layer. | Occlusion can protect the focal point or show that an object is behind another. A reveal becomes animated when a time value drives its mask or opacity; “wipe” and “dissolve” are combinations of these operations. Layer order can also hide an important subject or text. [Raster, vector, and DOM](knowledge/Raster%20vector%20and%20DOM.md), [shaders and 3D](knowledge/Shaders%20and%203D.md), [Attention and hierarchy](theory/Attention%20and%20hierarchy.md). |
| **Repeat with controlled variation** | A source, instance index, ranges or rules, and possibly a stable random seed → create related instances → a field, texture, pattern, crowd, sequence, or family of marks. | Repetition can establish rhythm and style; variation can prevent every instance from looking identical. The rule should preserve the intended family resemblance, and a fixed seed is needed when a repeated render must reproduce the same instances. [Visual identity and style](theory/Visual%20identity%20and%20style.md), [deterministic rendering](knowledge/Deterministic%20rendering.md). |

These patterns assume no particular rendering tool. HTML, SVG, Canvas, WebGL, a 3D scene, or an editor's layer stack can each express a different subset of them. The [authoring approaches](knowledge/Authoring%20approaches.md) page treats the source representation, the renderer, and the delivery path as separate choices. Pixel art, for example, constrains the grid, the set of shapes, and the sampling of several patterns. It is a visual style and brings no timing system of its own. [Pixel art and stylization](knowledge/Pixel%20art%20and%20stylization.md).

## Make change legible in time

| Pattern | Input → operation → output | Design relation and limit |
| --- | --- | --- |
| **Evaluate a property at a chosen time** | A time or frame number, a starting value, and a curve, keyframes, or rule → calculate the value at that instant → position, scale, opacity, camera pose, filter amount, shader input, or sound parameter. | This supports controlled motion and direct inspection of a particular frame. An accumulated simulation needs a defined history or bake before an arbitrary frame can be reproduced. [Time and motion](knowledge/Time%20and%20motion.md), [deterministic rendering](knowledge/Deterministic%20rendering.md), [Temporal visual rhythm](theory/Temporal%20visual%20rhythm.md). |
| **Schedule a meaningful event** | A named event, start time or beat, duration, and relation to other events → place it on a common timeline → an event that several visual or audio rules can read. | A shared event can make a reveal, impact, caption, and note respond to the same moment. The event's audible or visible peak may differ from its trigger time, so the intended sync landmark must be checked in playback. [Audiovisual synchronization](knowledge/Audiovisual%20synchronization.md), [Temporal visual rhythm](theory/Temporal%20visual%20rhythm.md). |
| **Carry or break correspondence between states** | Two scene states and any element, shape, color, position, camera direction, or sound meant to persist → declare what corresponds across the boundary → a cut or transition with a readable relation. | A shared object or motion path can show continuity; a cut can establish a new idea. A smooth morph may imply an identity that the story does not intend. This is a design relation that placement, time mapping, and compositing can render in different ways. [Grouping and continuity](theory/Grouping%20and%20continuity.md), [transitions and continuity](knowledge/Transitions%20and%20continuity.md). |

Readable text combines a source, a measured layout, an appearance, and time. Its reading time begins when the words are complete and still; a long entrance can use up most of it. A character reveal meant to show characters as a reader perceives them also needs a unit that knows the language. See [moving-text legibility](theory/Moving-text%20legibility.md) and [typography in motion](knowledge/Typography%20in%20motion.md). Applied to a camera or a projectile, the same time curve may serve a different visual purpose; the [theory pages](maps/Theory.md) help name it.

## Make and relate sound

| Pattern | Input → operation → output | Design relation and limit |
| --- | --- | --- |
| **Shape one audible event** | A recording or generated source, onset, envelope, pitch or playback rate, timbre, and level → render a cue → a sound with an attack, body, and ending. | A short transient can mark an impact; a slow attack can create anticipation. A waveform's start and perceptually important onset can differ. The cue needs to be heard in the context of the full piece. [Audio synthesis](knowledge/Audio%20synthesis.md), [sound sources and voices](knowledge/Sound%20sources%20and%20voices.md), [groove and feel](knowledge/Groove%20and%20feel.md), [Temporal visual rhythm](theory/Temporal%20visual%20rhythm.md). |
| **Combine sound by role** | Speech, music, ambience, and effects with timing and gain or processing → mix them → a soundtrack. | Relative level can make one source foreground and another background; under speech, the gap between voice and music can be measured in LU. Numerical peaks and loudness reveal technical problems, while listening determines whether the hierarchy and character work. [Audio synthesis](knowledge/Audio%20synthesis.md), [dynamics and spectral carving](knowledge/Dynamics%20and%20spectral%20carving.md), [space and delay](knowledge/Space%20and%20delay.md), [mastering and delivery](knowledge/Mastering%20and%20delivery.md), [music under voice-over](knowledge/Music%20under%20voice-over.md), [accessibility and perception](knowledge/Accessibility%20and%20perception.md). |
| **Align media to a common time** | Event times, frame rate, sample rate, clip offsets, and preview or export clocks → map each event to frames and audio samples → related events remain aligned in the rendered piece. | The video frame, audio sample, browser display, and browser audio clocks have different units and behavior. A shared event list reduces accidental drift; the muxed file still needs joint viewing and listening. [Audiovisual synchronization](knowledge/Audiovisual%20synchronization.md), [sound and picture on one beat grid](knowledge/Audiovisual%20synchronization.md#sound-and-picture-on-one-beat-grid). |

A beat-led video can use recorded or synthesized music, and its visual and audible events are placed at chosen times. The [Stage intro](cases/Stage%20intro.md) and [FOXTALE](cases/FOXTALE.md) cases show two reported uses of this link and state what the chatlog verifies. [Two soundtracks](../video-knowhow-craft/cases/Two%20soundtracks.md) compares the AX DAY reconstruction's score with SLASH_MY's, and the [Soundtrack code case](cases/Soundtrack%20code.md) gives the line references and values behind that comparison.

## Turn the system into evidence

| Pattern | Input → operation → output | Design relation and limit |
| --- | --- | --- |
| **Sample a specified state** | Scene inputs, a requested time or frame, output dimensions, and loaded assets → render and capture → a still, frame sequence, audio buffer, live preview, or encoded file. | A seekable state allows targeted inspection and retries. A preview and an exported frame can differ if they use different clocks or if fonts, images, simulation state, and device settings are not ready or fixed. [Deterministic rendering](knowledge/Deterministic%20rendering.md), [capture and encoding](knowledge/Capture%20and%20encoding.md). |
| **Compare output with the intended effect** | Rendered frames and sound plus a question about legibility, hierarchy, motion, sync, sound, or playback → inspect the relevant samples and revise a source or parameter → a new version and evidence about the change. | Code can make the same error across many frames. A contact sheet can show layout and scene structure; playback exposes pacing and collisions; listening exposes musical fit. The final encoded file is the evidence for delivery behavior. [Verification](knowledge/Verification.md), [iteration and parameterization](knowledge/Iteration%20and%20parameterization.md), [delivery and color](knowledge/Delivery%20and%20color.md). |

The [capability boundaries](knowledge/Capability%20boundaries.md) page asks whether the shot you want has enough spatial, surface, motion, and performance information to render. The [recipes](maps/Recipes.md) page shows which combinations in the package have examples you can inspect, and its case links keep what was seen in the construction apart from visual judgments that were only reported.

Two [inspected creator examples](sources/Social%20examples.md) show other combinations built from the same operations:

- **A supplied interface inside a moving phone**: an app screenshot supplies the interface. Spatial placement fits it to the phone display, compositing handles the phone frame and what it covers, time changes the phone or camera view, and text roles add the short titles. The inspected Maintra video shows this combination. The creator reports supplying screenshots but did not link the project source.
- **The controls beside their result**: code, an easing curve, or a timeline becomes a visible source. Spatial grouping places it near the object it controls, and a shared time value ties the displayed parameter to the movement it produces. The inspected MotionGfx showreel shows these elements together; its linked engine source does not identify the exact showreel composition.
