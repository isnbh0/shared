# Techniques and approaches

An [operation](../Operations.md) describes a change from input to output. A technique picks a representation and an implementation that can carry it out. Start from the effect or constraint you need, then follow the route that fits.

- [Choose a visual representation](Choose%20a%20visual%20representation.md) for text, shapes, raster images, shaders, 3D, or an intentional visual style. [Authoring approaches](../knowledge/Authoring%20approaches.md) compares how these media can be put together.
- [Compose time and motion](Compose%20time%20and%20motion.md) for state, pacing, transitions, and evaluating a frame the same way every time.
- [Compose sound and synchronization](Compose%20sound%20and%20synchronization.md) for synthesized or prepared sound, timing relations, and playback clocks.
- [Inspect and deliver](Inspect%20and%20deliver.md) for playback checks, capture, encoding, color, and the delivered file.

If the question is what an audience notices or understands, go back to [Theory](Theory.md). When several techniques serve one aim, look at a [recipe](Recipes.md) and its evidence.

The graphics, animation, compositing, and encoding techniques in the package were in production use before LLMs existed. [Production lineage](../sources/Production%20lineage.md) links established examples to the choices made today. LLMs can help write and revise the code that uses those techniques.
