# Production samples

The [starter](../starter/README.md) is the skeleton: one page draws each frame from its number, one browser captures the frames in order, and a 16-bit score is muxed in with no loudness work. Start with [Production bootstrap](../knowledge/Production%20bootstrap.md), which walks through a first render and these samples in one workable order. Each sample is one working piece of SLASH_MY, the production John endorses, excerpted in John's workspace at its 2026-10-02 snapshot (audio `fd543f2a`), with the film's scenes, copy, and cues taken out. Each one replaces or extends one part of the skeleton, for when a film needs it. The samples keep SLASH_MY's page contract, which the starter shares: `<canvas id="c">`, `await window.ready`, `window.draw(frame, samples)`, the `?render` query (with `&scale=`, `&samples=`, and, for a page that reads it, `&fps=`), and `window.SCORE_EVENTS`, which the renderer inlines before any page script runs. Every file opens by stating what it does, when you need it, which part of the source production it generalizes, and what was generalized or left out.

| Sample | What it does | When you need it | Source (production component) |
| --- | --- | --- | --- |
| [capture.js](capture.js) | Opens the page in headless Chrome on the CPU raster path, waits for `window.ready`, pulls frames off `#c` as PNG or raw RGBA while the next one draws, and always closes Chrome. | Frames must come out byte-identical from run to run, and Chrome must not stay open after the last one. | the production's renderer: page open, frame grabber, browser shutdown, the worker's frame loop |
| [chunk-render.js](chunk-render.js) | Renders on parallel Chrome workers in 30-frame lossless 4:4:4 chunks, cached under a key of the source, the machine and the job, with a lock, and resumes from the finished chunks. | One browser is too slow, or a crash or kill must not lose the finished part of a long render. | the renderer's chunked workers; the production's render cache (source, environment, job keys, lock) |
| [delivery-encode.js](delivery-encode.js) | Joins the chunks into one H.264 High 4:2:0 file with BT.709 tags, x264 zones for fades and forced keyframes on whole-frame swaps, and muxes the mastered AAC by stream copy. | The file goes to a player or a platform that re-encodes it, and its color tags must say what the pixels are. | the renderer's delivery encode: x264 zones, mux, full pipeline, the chunk encode in its worker |
| [loudness-gate.js](loudness-gate.js) | Masters a WAV to AAC at a loudness target under a true-peak ceiling, measured on the encoded stream over up to three passes, then gates the delivered file. | The delivery has a loudness spec (such as −14 LUFS, ≤ −1 dBTP), and the AAC encoder's own overshoot must not break it. | the renderer's AAC stage, loudness measure, master-audio path, and the mux's delivery check |
| [master-loudness.js](master-loudness.js) | BS.1770-4 integrated loudness, a lookahead true-peak limiter, and the trim search that brings the limited mix to the target, all in Node. | The score is synthesized in code and should leave the synth already at the delivery loudness. | the score's loudness measure, mastering limiter, and trim search |
| [wav-writer.js](wav-writer.js) | Writes float stereo as 48 kHz 24-bit PCM with TPDF dither from its own seeded stream; digital silence stays zero. | The score leaves the float domain once, and that step should add a steady noise floor and give the same bytes every run. | the score's WAV writer and dither; the seeded stream from its beat clock |
| [seeded-streams.js](seeded-streams.js) | mulberry32, named streams per concern, per-event seeds keyed by beat, and a stateless hash and value noise. | Every frame and sample must be a pure function of time, and editing one part must not reshuffle another's randomness. | the beat clock's seeded stream; the score's named streams; the engine's hash and value noise |
| [beat-clock.js](beat-clock.js) | Beats to frames and back, beat ranges snapped to whole frames, a 16th-step groove grid, and the score's events recorded where played and read by the picture. | Picture sync points must come from the score's own record of what it played, never from a hand-copied table. | the beat clock's frame spans; the score's event record; the engine's sync-point agreement checks |
| [tokens.js](tokens.js) | Palette, margins, punch-in margins and type stacks in one Node-safe module, and a `ready()` chain that loads and measures every face before frame 0. | A value appears in more than one file, or the first frames come out in a fallback font. | the engine's shared-values block, punch box, fonts, faces, and readiness chain |
| [scene-registry.js](scene-registry.js) | Scenes as registered functions of beat over segments: which are live at a beat, how two hand off (fade and slide, self, overlap, or cut), a placeholder for a missing scene, and a loader that tolerates missing files. | Several people or agents write scenes in separate files against one timeline. | the engine's scene dispatch, segment cuts, hand-off rules, and placeholder; the page's script loader |
| [facts-lint-docs.js](facts-lint-docs.js) | One registry of shared values read from the modules that own them, pins that fail when a literal copy drifts, and generated doc regions checked for staleness. | The same number lives in the score, the page, QA and the docs, and an edit to one copy must stop the build. | the production's facts registry, lint pins, and generated-doc checks |
| [qa_av.py](qa_av.py) | `audio`: integrated loudness, true peak, clipping and DC on the delivered file. `sync`: where each sync point's visual change starts in the picture's change signal, against the event's beat. | Before a file goes out, and after any change to picture timing or the score. | the production's QA suite: audio loudness checks, seam and signal tooling for sync points |

## How they fit

- **Page**: [tokens.js](tokens.js), [beat-clock.js](beat-clock.js), [seeded-streams.js](seeded-streams.js), and [scene-registry.js](scene-registry.js) load as plain scripts in the page (`window.TOKENS`, `window.BEAT`, `window.RNG`, `window.SCENE_REGISTRY`) and through `require` in Node. They replace the starter's `tokens.js`, the clock in its `timeline.js`, and its single `scene.js`. Their names differ from the starter's, so a scene moved onto them has to change the names it reads.
- **Picture**: [capture.js](capture.js) → [chunk-render.js](chunk-render.js) → [delivery-encode.js](delivery-encode.js). They call `window.draw(frame)`, so the page takes its sample count from `?samples=` or its own default (the starter's is 4). They need `npm install puppeteer-core`, Chrome (set its path in `CHROME`), and ffmpeg on the `PATH`.
- **Sound**: the synth records its events with [beat-clock.js](beat-clock.js) and draws its noise from [seeded-streams.js](seeded-streams.js), [master-loudness.js](master-loudness.js) sets the level, [wav-writer.js](wav-writer.js) writes the WAV, and [loudness-gate.js](loudness-gate.js) makes and gates the AAC.
- **Checks**: run [facts-lint-docs.js](facts-lint-docs.js) at the project root before a render, and [qa_av.py](qa_av.py) on the delivered file (`uv run qa_av.py audio …`, `uv run qa_av.py sync …`).

## What has been run

**Checked (one machine):** on macOS 26.7.1 with Chrome 155, Node 24, ffmpeg 9.0.2, and puppeteer-core 25.13.0, every JavaScript file passes `node --check` and `qa_av.py` passes `ruff check`. Smoke tests of the pure parts passed: stream independence and the stateless hash; `frameSpan`, `hits`, `agree`, and the events file format; dither error within 1.5 LSB at 0.50 LSB rms, digital zero kept, and the same bytes from the same seed; a 1 kHz sine at −23 dBFS reading −22.99 LUFS against ffmpeg's −23; the limiter holding a full-scale tone at −2.00 dBTP; scene hand-offs at soft and hard boundaries; and stale regions, `--write`, and a drifted pin in a small facts project. A toy page went through the whole chain: chunk renders with two and three workers decoded to identical frames, a killed render resumed from 22 of 100 chunks, the delivery file carried all four BT.709 tags, the AAC measured −14.0 LUFS and −1.5 dBTP, and `qa_av.py sync` flagged the one sync point drawn 100 ms late and passed the others at 0 ms. `capture.js` also captures the starter's page with no changes to the page.

**Checked:** given only the `-colorspace`, `-color_primaries`, `-color_trc`, and `-color_range` output options, ffmpeg 6.0 (the ffmpeg-static build SLASH_MY encodes with) writes all four tags on a filtered encode, and ffmpeg 9.0.2 writes only the matrix and the range. So [chunk-render.js](chunk-render.js) and [delivery-encode.js](delivery-encode.js) also set all four on the frames with `setparams`, and ffmpeg 9.0.2 carries those into the file.
