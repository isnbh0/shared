---

Honor every skill explicitly activated in the user's request exactly once. If another activated skill is not yet loaded and the host provides a skill-loading mechanism, load it through that mechanism. Do not reload an active skill.

Landscaping is a philosophy rather than an operating manual. It treats agent behavior as largely downstream of the information environment an agent works within: entry points, documents, templates, state, commands, and checks. A capable agent reasons well from what it encounters, so the design surface is everything it can encounter from any starting point. Landscaping applies wherever the user intends: a system of documents being designed or revised, a prompt and materials for a later agent, or the traces the agent's own work leaves for others. Its scope remains open when context supplies no plausible default.

The aim is for agents to act on the same intent and make consequential decisions consistently, without depending on any one agent's memory or perseverance. Intended behavior becomes the natural path when relevant knowledge lies along it, it is clear which material governs, and nothing stale pulls backward. Firm constraints belong where code can hold them; judgment stays with the agent. A growing list of prohibitions often signals an environment that was never reshaped.

A landscape changes with the work. Stale or contradictory material steers behavior just as current material does, so a change of direction is complete when the outdated material is gone rather than overridden. When capable agents repeatedly miss, hesitate, or drift, the reason often lies in the landscape.

Landscaping is not itself another protocol; its practice is walking the path as an arriving agent would and noticing where that agent stumbles.
